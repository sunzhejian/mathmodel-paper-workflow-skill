# 向使用者询问论文与图示模板

模板选择是新稿和大幅改版的入口决策，不是每轮文字修订都重问。先读取项目 AGENTS.md、.mathmodel/paper/config.json、用户当前消息和已有可编辑源。**先确定要完成哪一类工作，再谈模板。** 只有论文工作方向仍不清楚时，先给使用者一个单选题；交互选项工具可用时用其选项，不可用时列编号，允许使用者补充说明：

> **这次主要希望我完成哪类工作？**
>
> 1. **继续修改现稿**：以最新版论文为基线，按反馈修正文、图表或格式。
> 2. **用已有求解结果写论文**：模型、程序和结果已具备，重点完成论证、图表与成稿。
> 3. **从零到完整论文及相关材料全交付**：从题面和附件开始，逐问建模求解，交付可复现代码、原精度结果与题设电子文件、图表及可编辑源、论文 PDF/Word、要求的附录和支撑材料，并完成验收。
> 4. **只审查现稿**：检查模型、数值、引用、匿名性和排版，给出可定位的问题清单。
> 5. **只制作图示**：按论文内容或参考图制作可编辑示意图、流程图及导出图。
> 6. **只修排版**：在不擅自重算模型的前提下处理分页、公式、图表和格式。

选项表达**主要方向**，不是禁止后续补充任务。按现有材料删去明显不相关的选项；用户已明确“只完善 skill”“只修首页”“只改图”时，直接按该方向做，不为走流程再问。选定后只问该路线缺少的关键材料和交付格式：选 3 时核对题面、附件、赛事要求与电子成果清单，不能因选了“全交付”就编造缺失数据；其他选项不强加整套材料。将方向、交付物和保留范围记在项目工作记录中，区分用户答复与代理推断。之后才运行 scripts/template_inventory.py --project-root 项目目录 --category paper --configured-family 查看当前赛事的论文变体，需要流程图时再用 --category diagram，需要特定数据图时用 --category data-figure。只有用户想换赛事模板时才列全量候选。脚本只盘点，不复制文件，也不输出队号和联系方式；默认全量 JSON 供程序使用，不要直接把它贴给使用者。用户本轮已经明确指定的模板、排版引擎或参考图优先；不同来源冲突时说明冲突并询问，不能默默改写既有论文。

## 问什么

大方向确定后，新建论文或用户说“换个模板、做成优秀论文风格”时，给出当前配置及两三个有实际区别的选项，问**论文模板与排版引擎**。例如：

> 当前项目配置为国赛 CUMCM，已有 LaTeX 入口。此次沿用现有版式、改用同赛制 Typst 版，还是按你提供的 Word/PDF 模板重建？若沿用现有版式，我继续写作，不改项目配置。

若任务需要技术路线图、研究框架图或用户给了参考图，再问**非数据型图示的版式**。选择基于图要表达的关系：

| 要表达的内容 | 给使用者看的候选 | 本地模板 |
| --- | --- | --- |
| 从问题到评价的整篇路线 | 五带纵向技术路线 | roadmap-5band |
| 每阶段研究什么、用什么方法 | 三栏研究框架 | framework-3col |
| 阶段推进、分支和汇流 | 三栏阶段流程 | stageflow-3col |
| 多个子问题的横向步骤 | 横版任务流水线 | taskflow-land |
| 特殊几何、物理边界或用户参考图 | 专题线稿 / 按参考图重绘 | 不硬套上述四模板 |

问话可写成：“这张图重点是全文路线、逐阶段研究内容，还是各问的执行流程？我建议 X，因为它能清楚呈现当前 A→B→C 的关系；也可以用你发的参考风格重绘。”可提供实际 preview.png 路径供用户预览；需要同时比较四款时，运行 python scripts/preview_diagram_templates.py --output 项目目录/diagram-options.png 生成本地对照图，再展示给用户。该图仅用于选择，不进入论文或公开仓库。用户未要求示意图且正文没有必要的非数据关系时，不为凑图要求选择模板。

**数据图**另作决策。MathModelAgent 的 11 个科研图模板适用于 SHAP、ROC、泰勒图等特定数据结构，默认脚本含模拟数据。先检查本题结果是否具备相应变量和统计含义；若不匹配，应直接制作可追溯的温度场、时序、剖面或验证图，不向用户推销不相干模板，更不能把模板模拟数据写成赛题结果。有匹配项时最多推荐两三个，并说明需要以实际结果替换数据后再检查。

## 何时不问与怎样记录

- 用户已明确选定模板、已有项目源需小修、或配置与本轮要求一致且更换会破坏已修改附录时，沿用已有选择；只向用户简短说明当前使用哪套模板。
- 重大改版、模板不存在、用户给的参考图与配置冲突、或 PDF 想转为可编辑 Word 且保真要求不明时，尽早询问一次。答案尚未到来时可继续整理题意、数值证据和图表清单，依赖模板的排版工作等答案或按已说明的合理默认推进。
- 将已确认或有依据推断的决策写进项目的 reports/template-decisions.json；再次询问前先读这份文件。记录每个选择的类别、目标图/论文、模板 id 和来源依据（user、project-config 或 inferred），不能把项目配置自动伪称成用户确认。数据图若套现成模板，另记 source_data 和 simulated_data_replaced=true；不使用模板时记 custom 与真实数据路径。只记录必要偏好，不把身份字段复制到匿名正文或公开技能仓库。
- 使用内置模板时只在项目入口尚不存在时复制完整模板；自定义模板从用户给定路径读取。切换模板后单独验公式、图片、页码与 Word/PDF，不以“同属 CUMCM”假定输出等价。
- 国赛 CUMCM 项目配置可保存题号、队号供非匿名环节使用，但匿名论文首页从论文标题起排，不在标题上方生成“题号/题目：A”或“参赛队号”抬头。实际编译后核对第一页，必要时运行 `pdf_workflow.py audit --cumcm-anonymous --project-config .mathmodel/paper/config.json`；只改项目本地论文源，不改子模块原模板或项目配置。

记录格式示例（按实际选择增减项目，不要预写未选图）：

~~~json
{
  "decisions": [
    {"kind": "paper", "target": "main", "choice": "cumcm-latex", "language": "zh", "basis": "user"},
    {"kind": "diagram", "target": "roadmap", "choice": "roadmap-5band", "basis": "user"},
    {"kind": "data-figure", "target": "drying-profile", "choice": "custom",
     "basis": "inferred", "source_data": "results/p3.npz"}
  ]
}
~~~

运行 python scripts/validate_template_decisions.py reports/template-decisions.json --project-root 项目目录，检查 id、配置变化、源文件和图形模板是否可用。该工具只验证文件与清单一致，不能证明使用者确实说过“确认”，也不代替模板预览和图形语义审查。若记录与本轮用户新选择冲突，以新指示为准，更新记录并写明变更原因；无需重复询问已明确的部分。
