# 字体、图件与最终渲染合同

用于新稿排版、跨引擎图件导入及发生字体/黑块/丢字问题时。先读取已选择模板和项目约束；修工具和模板，不把某次修稿的字符串替换写成通用科学纠错。

## 先读取实际模板结构

模板选择、实际入口/宏、摘要与正文结构合同、编译 PDF 验证连续执行，来源记录见[模板选择](template-selection.md#将模板选择落实到结构合同)。新稿使用已经选定且存在的完整模板，已有稿保留当前入口。摘要后换页等规则若已在上游具体模板实现，沿用其宏；不能因宿主装配方便而另写主文件，之后把失效归因于上游缺功能。

摘要独页及页数由当前用户/赛制/模板确定。本次中文实例要求摘要独立一页，记录摘要起止页与正文起始页后核验实际 PDF；摘要页不能出现正文标题/段落。声明、Summary Sheet、目录与附录按各自赛制处理，不把中文摘要合同套到所有模板。`summary_guard` 或 MCP `ensure_summary_page` 可用时先查看真实接口和支持范围；它们仅处理/检查声明的结构，不能代写完整摘要或证明摘要覆盖全部问题。源里有换页命令但未调用、摘要溢出、正文标题跨页等仍须实际编译后检查。

## 先选择，再验证字体

中文学术稿先读取模板和用户指定的正文、标题、西文及数学字体。没有指定时，可推荐宋体/思源宋体正文、黑体/思源黑体标题、Times New Roman 或相应开源西文字体的组合，再记录本项目的选择。字号、边距、行距按本次合同，不从过去某篇稿固化到所有比赛。

“字体文件存在”不是已使用。编译前盘点引擎识别的真实family，缺字体报告具体项，不悄悄替成无衬线。编译后检查PDF嵌入字体及字体尺寸，并看正文、标题、数字与公式。数学字体有专门职责，不能强行用不含数学字形的中文字体替代。

先检查短页：一段中文正文、中文标题、数字/西文、典型公式与当前要用的图。最终稿还要抽查这些位置的实际字体职责和缺字警告。PDF 中出现所选 family 只证明该字体被使用过，不能证明整篇正文采用它；不能因为页码或图内标签含宋体而让无衬线正文通过。

图中单位、上/下标与数学符号也检查实际字形。正文宋体正常不能掩盖图内方框或 LastResort 等缺字回退；不要过滤缺字警告后称通过。图件说明逐项对照实际坐标轴、位置、参数扰动幅度和可复现脚本，编号能跳转不代表图意对应。发现排版或语义错配时修其源并重新导出，再看最终嵌入页。

## 按目标引擎选择图件

保留真正可编辑的图源与目标软件导出。SVG 不总能跨引擎显示：`foreignObject` 里的 HTML 文字、CSS `light-dark()`/变量、字体及外部资源引用可能在浏览器正确而在排版引擎丢失。对目标为 Typst 的图先查这些结构；发现风险时先用实际引擎核验，已知不兼容的图停止直接嵌入，选择可移植 SVG 或从同一图源导出的高清 PNG。不能仅删掉 `foreignObject` 或 CSS 警告而同时丢失标签/颜色。

导出前绑定图源与最终放置宽度；PNG 按保留像素计算 `DPI = 像素宽度 × 25.4 / 放置宽度(mm)`，目标 DPI 按本项目合同确定。矢量 PDF、`.drawio` 等原源继续交付。转换后核对标签、箭头、方向、颜色含义和裁切，格式适配不能改变模型关系。缺导出工具时保留源、说明具体未完成项，不以空框或黑块代替图。

不通过删除标签、整图变黑、截图覆盖正文来获得编译成功。格式替换是渲染适配，不能重绘或改变数据/模型关系。预览必须来自要交付的实际PDF，源PNG或单独模拟的同坐标图不能证明PDF里显示正确。

本仓库的 `scripts/rendering_guard.py` 可检查 Typst SVG 的部分兼容风险、检查声明字体的存在、按明确合同调整支持的顶层字体声明。自定义模板不能可靠匹配时应读源修订，不猜测替换。它的 PDF 检查只核对 family 存在与选定页数下限，不验证字体职责、文字清晰度、箭头语义或整篇质量；搭配最终 PDF 预览使用，不能把 `passed` 写成“渲染已全面通过”。

## 让问题回到负责的步骤

报告具体缺陷与最早出错处：模板结构/宏调用、字体选择与发现、图源语义、导出格式、嵌入兼容、公式表达或分页。反馈包含文件/页/对象、实际现象、检查证据及应返回的阶段；不要只回传“检查不通过”。代理读报告后修对应源并再次编译；不由宿主悄悄修文字后把原模型记录为通过。科学内容有错误时给证据，保留原答复与模型的新答复；只做机械格式修订也记录对象和范围。

对完整长稿，结果一致、字体符合合同、图可读、公式正确、页数与留白分别记录。任一必要项失败时保持候选状态。末页短文献的正常结束与正文整段推页分开人工判断，不能靠添加横线或孤立字符骗留白检测。

## 默认检查公式整体性

Typst 的 `$x_t$` 是行内数学；`$ x_t $` 的首尾空白会将它提升为独立展示公式。正文中把变量都改为后一种写法，再加全局编号，会形成大量孤立变量和无意义公式号。`numbering` 本身不是这类故障的根因，不能用关闭全部编号掩盖碎裂关系。

按语义生成整体：`库存为 $I_t$，入库为 $q_t$。` 保持一段；关系式 `$ u_t = min(y_t, I_(t-1)+q_t) $` 在一个数学块中。等号、函数、分式、括号、运算符和相应操作数不能分散在普通文本与若干编号单变量之间。方程组用一个 `cases`/`aligned` 整体，编号对应完整的推导或模型关系。

数据列名、文件名和代码标识使用原样文本/代码样式，如 Typst `#raw("demand_tonnes", block: false)`。只有已定义的数学符号才转为数学，不能用带下划线的词形匹配批量推断变量；格式转换应保留原来的行内/展示数学类型。

常规交付阶段运行 `check_formula_integrity.py` 或宿主等价检查，不依赖使用者再次指出截图问题：

```sh
python scripts/check_formula_integrity.py paper/main.typ --pdf paper/main.pdf --output reports/formula-structure.json
```

附录按用户范围排除时，用确切 `--stop-at-heading` 及实际 PDF `--pages`；源码与 PDF 范围分别声明，不能从标题自动猜页码。检查器不改输入，拒绝报告覆盖/别名指向论文。严重碎裂为 `fail`，必须返回对应写作/转换源修正后重编译、重检；`review` 是需要查看的疑点，不能自动当错式重写，也不能不读就给整篇通过。

当前受限论文工具的 `compile_and_check` 已接入源码及实际 PDF 结构检查，严重错误不能覆盖此前接受的成品；警告在结果中保留 `formula_review_required`。这是该工具路线的自动执行，其他宿主按核心默认交付步骤使用同等检查。未解析的导入、宏、栅格公式和数学含义仍需实际审阅，结构检查通过不证明推导正确。

## 两种外部模型评测必须区分

- 纯文本任务：模型不能读本机文件、执行程序或编译；只能评价其返回的内容。明确工具不可用，不要求或接受模拟工具调用。
- 项目操作任务：模型实际读取所需 skill/参考、选择参数、调用项目工具、检查真实反馈并修订。记录工具名称、调用结果和最终文件；宿主执行固定工具、审查产物。若宿主补写科学内容或自行决定模型/字体/图源修法，单列该干预并保留原模型成绩，不能把其计为模型自主完成。

给代理精简的当前任务入口和可用工具，不一次塞入所有阶段指令。输入、初版失败、工具诊断、模型修订与最终验收分别保留。回归包含故意错误字体、SVG外来文字和阶段多余项，验收必须能拒绝这些失败样本。
