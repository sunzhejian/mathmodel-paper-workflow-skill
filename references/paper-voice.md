# 论文表达：清理制作痕迹，保留有依据的强调与论证

用于摘要、正文、题注和模型评价的写作或润色。用户说“穿帮”时，先结合原句判断问题：制作记录、模糊指代、虚构主张与多余辩解的修法不同。已经明确的局部修改直接完成；不为这项审查重新询问比赛模板，也不改用户保护的附录。

## 判断一句话的作用

| 原句的作用 | 处理方式 |
| --- | --- |
| 强调核心方程、关键参数或主要结果 | 有推导或结果支持即可保留；少量加粗或细黑框，公式编号在框外 |
| 解释模型选择、反驳具体替代解释、说明误差或适用范围 | 保留所需条件和理由，优先写条件、证据及其含义 |
| 表达真实不确定性，例如参数只能区间辨识、外推缺少观测 | 保留限定，说明不确定性来自数据还是假设；不能润色成确定结论 |
| 先道歉、空泛自我贬低、反复防备同一种假想质疑 | 合并或删除无信息部分，用现有证据直接说清研究内容 |
| “按你的要求”、制作指令、内部交接文件或验收状态 | 从科学正文移出；确有学术内容时重新表述，记录留在 `reports/` 或 `qa/` |
| “全面领先”“显著提高”“充分证明”等没有对应证据 | 回到推导和结果核对，缩小或撤回主张；不凭措辞造优势 |

**强调与必要的防御性论证允许存在。** 不机械禁止“值得注意”“需要指出”“不能”“并非”“可能”或对比句。判断标准是它是否改变结论的成立条件、澄清概念或帮助读者正确使用结果。“可能”有数据依据时保留；“显著”涉及统计判断时需要相应检验，而不只是语气更强。

## 数模中的具体处理

以下是合成措辞示例，不能把例中的条件、数值或检验当成用户项目已经取得的结果。

| 情形 | 可采用的表达或动作 |
| --- | --- |
| 参数只在给定温度下标定，却被写成通用关系 | 写清标定温度和适用域；若结论离开该限定会被误解，摘要与结论也保留它 |
| “数值收敛不能说明现实预测准确” | 这是必要的概念区分，可保留；有实验数据时再分别报告预测检验 |
| 表题为“主要符号说明（一行一符号）” | 表题写“主要符号说明”，排版落实逐行列符号 |
| “根据 RESULTS_REPORT.md，本问已通过检查” | 核对真正支持的方程、数据和结果，再写其科学结论；文件存在与检查通过不足以推出模型有效 |
| “模型优点是有独立脚本、数据回读和清单” | 复现材料放在约定位置；模型优点评价其可解释性、可行性或性能，并给对应依据 |
| “模型可能或许在一定程度上有一些优势” | 根据实际比较写哪项指标、相同条件下怎样变化；证据不足时保留准确的不确定性或删除优势主张 |
| 某方案误差更小、耗时更长 | 两项指标及比较条件都报告；权衡如何影响推荐由题目目标决定 |
| 方案在一段参数区间最优，区间外排序改变 | 写清区间与边界的并列情形；限定是结果的一部分，应与推荐同处 |
| 英文稿 “may potentially suggest that X could possibly…” | 去掉重复保留词，按证据选 “is associated with” 或 “suggests”；相关关系不能改成因果关系 |

审稿模拟提出的问题也要分类：已经证实的错误要修；需要核实的问题去查证；可选扩展由本次范围决定。不能把审稿意见逐条搬成“模型不足”，也不能因改写更自信而删除影响核心结论的不利结果。

## 执行与复核

1. **确定范围。** 选择匿名论文的实际源文件及题注。附录受保护时排除对应文件；真实 AI 声明和工具详情按它们的用途与事实单独核对。
2. **先核对主张。** 关键句对应到题面、推导、原精度结果或文献。检查适用条件、比较口径、因果强度、可行域和最优性；缺证据不能靠改句式补上。
3. **按句子作用修改。** 保留有用强调和必要论证，减少重复辩解，清理对话与制作痕迹。局部修订不另加结论、数值或未做过的实验。
4. **逐句比较含义。** 原稿与修稿的数字、单位、正负方向、范围、阈值是否含等号、不利结果、引用和真实 AI 使用信息均保持准确。修改格式不改变科学主张。
5. **筛查并看成品。** 自动结果逐条判断，编译后通读摘要、图表题注、每问结论及模型评价；修订记录写在后台。

## 自动筛查的用法与边界

```sh
# 只选论文源；不要把仓库 README、审稿记录和 skill 文档当论文扫描。
python -X utf8 scripts/check_paper_voice.py paper/main.tex paper/sections --json

# 分文件附录不在此次范围时，排除模式相对于每个输入目录。
python -X utf8 scripts/check_paper_voice.py paper --exclude 'appendix/*' --exclude 'ai-details/*' --json

# 单文件 TeX 且正文后有字面 \appendix，只有保护附录时使用。
python -X utf8 scripts/check_paper_voice.py paper/main.tex --stop-at-appendix --json
```

结果包含 `error_count`、`review_count`、具体位置和理由，以及实际选中的 `checked_files` / `excluded_files`。`error` 标出明确制作指令或助手自述候选，退出码为 1，仍需看上下文确认；内部文件引用和容易因研究对象产生歧义的制作词列为 `review`，退出码为 0 但 `review_required=true`。两类均不自动删改原文。缺少源或排除后无文件退出 2，不能报成检查通过。

工具忽略 TeX 注释及若干常见代码块、Markdown 围栏代码和 HTML 注释，保留原行号；行内格式化的内部文件名仍能提示。它不展开 `\input` / `\include`，不理解自定义宏、条件编译或所有格式语法；须把实际正文分文件一起传入，正文/附录边界不明时先确定真实范围。声明里的提示词、代码示例等按上下文人工判断，不能从措辞筛查推断真实 AI 使用情况。

这项筛查定位有限的制作痕迹，不验证数学正确性、全部引文、整体自然度或作者身份，不产生 AIGC 百分比，也不保证通过某种 AI 检测。无证据夸张、模糊指代和重复防御主要依靠上述内容复核。
