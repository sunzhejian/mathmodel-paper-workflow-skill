# 2026-10-01：真实模型试用与 skill 修订

本轮用使用者授权的套餐，在 Codex CLI 0.144.1 中执行匿名合成任务。实际尝试千问 Token Plan 的 `qwen3.8-max`、火山 Agent Plan 的 `doubao-seed-2.1-pro`、火山 Coding Plan 的 `glm-5.3`。这里是请求的调用名称，未独立核验后台精确版本。千问返回 `InvalidApiKey`，没有建模答案，不能评价它的能力。密钥只保存在本机私有位置，不进入本仓库和提示词；没有切换按量付费端点。

## 任务与实际范围

[匿名任务](../examples/model-trials/tasks.json)包含混合运输优化和潜在投票推断，要求模型、计算结果、Python源码、LaTeX片段、英文Summary及建议函。基线与新数据共四个小型案例；新数据运输题有三个方案在切换点同时最优。排名按所给综合得分定义解释，检查器记录该解释并提供代回与反例；真实题面不明确评分对象时需先澄清。

共8个解题会话：6个交出答案，其中1个原始JSON不合法；另外2个分别为千问鉴权失败、GLM中档推理响应长度截断。连通性探测不计作解题测试。有效路线完成基线、修改后的新数据测试，并分别对GLM旧题与豆包新题再次检查；模型未使用工具。主动提供的三个skill文件、任务和输入哈希见[评测记录](../examples/model-trials/observed/evaluation.json)。CLI自身系统提示词与已安装技能元数据仍存在，不能称为完全隔离的裸模型试验。

## 结果

| 试用 | 实际发现 | 更新后检查 |
| --- | --- | --- |
| 豆包基线 | 数值和JSON正确；审查后执行源码8个参数案例均与参考计算一致；公式片段直接编译通过 | 用新数据继续测，不能从基线正确推断全题型正确 |
| GLM基线恢复 | 中档响应截断；低档交出答案，但JSON字符串有6个裸换行；零值被写成“没有支持” | 保留原文及格式修复副本；同题低档复测原始JSON可解析，结构性零值解释正确 |
| GLM新数据 | 最优方案、三个并列方案、0.65排名下界、JSON和零值解释正确 | 数值/存在性检查16/16；人工编译发现公式长行越界，尚非整稿排版通过 |
| 豆包新数据 | 运输正确，投票下界错误；将综合排名替换为粉丝排名，给出0.5而应为0.65；公式缺数学环境 | 补充指导后仍为15/16，排名错误保留；数学环境可编译，但长行仍越界 |

“16/16”只是列明的数值和产物存在性检查，不能表示完整论文正确。GLM原始格式修复后的16/16不能记成原答复直接通过。初版检查器将千位逗号拆词，把豆包101词的Summary误报为114词；已修正为声明的空白分隔口径，而非删改正确答复以提高分数。

豆包错误的明确反例是：取粉丝占比 `p_A=0.575`，原式给出 `s_A=0.47`、`s_B=0.53`。该值落在模型声称的可行区间内，却不满足A综合分领先。检查器现在输出这种反例，而不是只说“检查失败”。

## 程序、公式与精度

维护者先人工审查模型源码，再在不含凭据的环境执行。多数源码在两组输入及端点/切换点8个测试中均正确；GLM同题复测改用精确分数计算，输入浮点近似 `10000/9` 时返回唯一方案，因此与采用容差的参考器有一项不一致。用 `Fraction(10000,9)` 明确表示精确切换点后，正确返回2、3、4次发射的三个并列方案。该现象记录为输入精度与并列口径差异，不能混称为普通求解错误或直接抹去旧结果。

审查后的片段使用现有XeLaTeX、12pt A4与2.5cm边距夹具实际编译。豆包首次新数据片段失败，复测能编译；GLM新数据与GLM旧题复测、豆包新题复测仍有长行越界。此夹具只验证片段插入情况，不是实际论文，也不证明所有符号、单位或最终版式已验收。

## 进入 skill 的修订

- 增加潜变量的点识别/集合识别与置信区间区分，结构性零值与未发生记录的处理。
- 方案建议区分名义点和参数范围，检查切换与全部并列最优。
- 综合排名按完整评分定义比较，边界和两侧代回原式核对。
- 机读交付检查字符串转义和实际解析；原答复与人工修复分开保留。
- LaTeX片段检查插入环境与实际编译，不能用字符串存在代替排版验收。
- 新增离线[提示词/参考检查器](../scripts/model_trial.py)、[单次编程工具试用器](../scripts/run_codex_trial.py)、原始[匿名答案](../examples/model-trials/observed)与保护密钥/旧产物的回归测试。

这轮改善了交付和检查能力，未证明豆包排名推断已改善。后续应围绕仍失败的推导和公式版心继续测，并增加不同领域的新任务；不能为让某道固定题通过而把答案或该题参数写进skill。研发未修改任何正式竞赛论文，也未创建长期模型调用任务。
