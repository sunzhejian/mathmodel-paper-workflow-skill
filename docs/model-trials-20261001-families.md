按使用者指定的三家模型完成了一轮有限试用，调用名为 `deepseek-v4-pro`、`glm-5.3`、`kimi-k2.7-code`。Kimi K3只作一次恢复尝试，超时，不计作通过。套餐仍采用已有火山Coding Plan，未转到按量付费端点。工具为Codex CLI 0.144.1和OpenCode 1.18.34；调用名未独立证明后台精确模型版本。

## 同题内容与范围

## 一处实际错误的修复链

DeepSeek新源码用 `(D+R-1)//R` 确定发射数量上界，把整数技巧套到连续吨数。以需求0.4吨、上限0.15吨、每次250kg运力、固定成本1、单价10为例，原函数返回空列表，尽管有可行运输方案。

修复请求只给出这一个失败输入和原源码，不给参考答案，要求按原模型修正而非硬编码。模型改为精确分数上取整 `-((-a)//b)`，分别确定最小可行与最大有用发射数量。维护者读源后实跑：8个题内案例、3个原探针以及2个新探针，共13个不同输入通过。新探针的350kg、275kg运力和非整数吨数未进入修复提示词；[输入](../examples/model-trials/solver-probes-unseen.json)在运行后作为证据公开。

首页制图时依据执行记录重新去重，纠正了原说明把总数写成14的计数错误。两批检查分别为11和10个案例，其中8个重复，因此为 `11+10-8=13`。原始模型答复和逐次检查结果没有更改；图与汇总由同一生成脚本读取实际记录。

## 修进 skill 与工具的内容

- 写JSON后读取一次并把源字段原样落盘，检查实际语法和编译，避免双重转义；普通LaTeX文字按语境转义特殊字符，读者标签采用自然场景名。
- 分清连续物理量与离散决策，避免错误上取整；分清可行域和经过支配分析缩小的搜索集合。
- 排名参考器支持空集、完整区间、严格端点和裁判权重1；缺字段不能充当显式空集。
- 增加阶段拆分/合并、实际代码和公式检查、OpenCode可选接口；不同客户端、截断与失败不混成成功答案。
- 修正检查器的精确分数桥接和提示词字节哈希。GLM的分数字符串不是数学错误；早期Windows换行转换造成的旧哈希差异保留并说明。
